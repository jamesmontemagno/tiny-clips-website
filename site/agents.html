Set up Agent Control

Let an AI agent on your computer take screenshots, record, and edit with Tiny Clips, with the permissions you choose.

Agent Control is off by default. Nothing can connect until you turn it on. Tiny Clips provides the tools, not an AI model, so bring your own agent.

What agents can do

Agents and scripts on your Mac or Windows PC reach the running app through a command-line tool or an MCP server. Once you grant permission, they can:

  • List displays and windows, then capture a chosen window, screen, or region without a picker
  • Read text from a target with OCR, without changing your clipboard
  • Annotate a screenshot, saving a new copy and leaving the original alone
  • Record video, GIFs, and Studio recordings using your saved recording settings
  • Trim a video or GIF, or save a single frame, as a new library item
  • Capture a long page as one stitched image
  • Edit a Studio project, including zooms, annotations, and captions, and export an MP4
  • List, reveal, and copy clips in your library

Tiny Clips can't click, type, or scroll in other apps. An agent needs its own browser or desktop tools for that, including to scroll a page during a scrolling capture.

Requirements

  • Tiny Clips 2.1 or later, running on the same Mac or Windows PC as your agent
  • The .NET 10 SDK, for the commands on this page
  • An agent with terminal access or support for a local stdio MCP server

A remote or container agent can't automatically reach the app on your desktop.

Turn it on

Turn on Agent Control from the macOS menu bar or Windows tray, or open Settings → Agent Control and turn on Allow agents to control Tiny Clips. If it has never been enabled, turning it on from the menu or tray opens Settings to the setup instructions. Leave the app running.

Install the plugin

We recommend the Agent Plugin. It bundles the MCP server and workflow Skills, so you don't need separate MCP configuration or a global CLI install. You still need the .NET 10 SDK and a one-time pairing.

VS Code

  1. Run Chat: Install Plugin from Source from the Command Palette.
  2. Enter the repository URL:
    https://github.com/jamesmontemagno/tiny-clips.git
  3. Confirm tinyclips is enabled in Chat: Open Customizations → Plugins, then start a fresh session.

VS Code downloads the plugin, so you don't need to clone the repository or register a marketplace.

GitHub Copilot CLI

copilot plugin install jamesmontemagno/tiny-clips

To update or remove it later:

copilot plugin update tinyclips
copilot plugin uninstall tinyclips

Other agents

Other Agent Plugins-compatible clients have their own install flow. If your agent doesn't support plugins, use the manual MCP setup.

Pair your agent

Pair once, from the same OS account your agent uses:

dnx TinyClips --yes -- pair --name "My agent"

Tiny Clips shows the requested permissions as checkboxes. By default the CLI asks for read, capture, record, edit, and export. Uncheck anything you don't want to grant, or check more, then approve. You can change them later in Settings without pairing again.

Verify the connection

Check the connection and find a capture target in Terminal or PowerShell:

dnx TinyClips --yes -- status
dnx TinyClips --yes -- capture.targets kind=windows

Take a first screenshot

Start a fresh agent session and ask it to take and inspect its first screenshot, using a window ID from the list. The equivalent terminal command is:

dnx TinyClips --yes -- capture.screenshot mode=window windowId=<returned-window-id>

Replace the angle-bracket placeholder with a real ID before running it. The result includes the saved path and image dimensions. Your saved screenshot settings determine PNG, JPEG, or WebP output.

Manual MCP setup

Use this only if your agent doesn't support plugins, because the plugin already configures the MCP server. Install the .NET 10 SDK and pair as above, then add a local stdio server to your agent's MCP settings:

{
  "mcpServers": {
    "tinyclips": {
      "command": "dotnet",
      "args": ["dnx", "TinyClips", "--verbosity", "quiet", "--yes", "--", "mcp"]
    }
  }
}

This is an example, not a universal configuration file. The settings location and surrounding JSON vary by agent. If you installed the global tool, use "command": "tinyclips" and "args": ["mcp"] instead. Restart or reload the agent's MCP connection after adding it.

  • Use dotnet dnx rather than the Windows dnx.cmd wrapper.
  • Keep --verbosity quiet so NuGet restore messages don't corrupt the MCP output stream.
  • Run the MCP process as the same OS account and environment you paired with.
  • Let your MCP client launch tinyclips mcp rather than leaving it running in a terminal.

For workflow guidance without the plugin, copy the folders you want from the skills folder into the directory your agent supports, such as a repository's .github/skills/ or ~/.claude/skills/ for Claude Code. Skills supply guidance only. They don't install the CLI, configure MCP, or approve access.

CLI-only setup

For scripts and terminal use, you can install the standalone CLI:

dotnet tool install -g TinyClips

Then use tinyclips in place of dnx TinyClips --yes --:

tinyclips pair --name "My agent"

To update an existing install:

dotnet tool update -g TinyClips

The CLI and MCP server share the same saved pairing token. Keep it private, and never include it in prompts, screenshots, issues, or source control.

Prompts to try

Give these to an agent with Tiny Clips CLI or MCP access. Tell it which app or project you mean, and review the result before sharing it.

Studio must be enabled for Studio commands. OS permissions still apply, and sensitive commands still ask for approval.

Security model

  • Off by default. The local listener exists only while Agent Control is on. When it's off, clients can't connect.
  • You approve each agent. Pairing shows every permission, with the requested ones checked, and you choose what to grant. Tiny Clips stores only a hash of the agent's token.
  • Sensitive actions always ask. Deleting, uploading, and discarding show an in-app prompt every time, even when granted.
  • No bypasses. Screen Recording, Microphone, and Camera permissions from your OS still apply. Commands return permission_required rather than prompting around them.
  • You can see it and stop it. The menu bar or tray menu shows when Agent Control is on and can turn it off immediately. Every command is written to a local audit log.
Agent permissions and when each one asks for approval
Permission Requested by default Once granted
read, capture, record, edit, exportYesRuns unattended
settingsNoRuns unattended
delete, upload, discardNoAsks every time. No answer within 120 seconds is a denial

The discard permission covers discarding or restarting a recording and discarding unsaved work.

Tiny Clips hands captures to the agent you connect, and that agent's own terms cover what happens next.

Troubleshooting

Common Agent Control setup problems and how to recover
Problem What to do
dotnet, dnx, or tinyclips is not foundInstall the .NET 10 SDK or tool, reopen the terminal or agent so it picks up PATH, and confirm the global .NET tools directory is on PATH.
Cannot connectStart Tiny Clips and turn on Agent Control. Check the listening status and endpoint in Settings. Local access doesn't bridge to a remote machine or container.
unauthorized or revoked accessPair again as the same OS account and environment the agent uses, with dnx TinyClips --yes -- pair or tinyclips pair, and approve it in Tiny Clips.
missing_scopeGrant the permission in Settings → Agent Control → Paired Agents → Permissions, which applies immediately, or pair again requesting it with --scopes.
permission_requiredGrant the OS screen, audio, or camera permission. On macOS, follow System Settings → Privacy & Security and restart Tiny Clips if required.
not_supportedCheck your app's version and feature settings, and turn on Studio for Studio commands.
MCP connects but calls failVerify the server runs locally under the same account, can find the CLI or SDK, and shares the pairing configuration. Then restart or reload the MCP connection.
Studio edit returns conflictRead the project again and reconcile changes with its latest modifiedAt and revision. Don't resend the old patch as is.

Change what an agent may do with Permissions, or revoke it, in Settings → Agent Control → Paired Agents. Turn Agent Control off to stop all connections. Activity → Open Audit Log shows local request history.
